DragonScript SpicyChat QoL — Full Guide

setup, filters, creator tools, backups, sync, Android and troubleshooting.

what is DragonScript QoL?

it's basically a lot of small (and some not-so-small) optional improvements for SpicyChat. filters, folders, shortcuts, backups, creator tools, memory helpers, performance options and loads of other stuff. you don't have to use all of it. i'd actually recommend you don't enable everything right away xD.

QoL is made by DragonScript, not SpicyChat. it can't unlock premium features, show hidden character definitions or guarantee that a bot follows instructions. it works with the site and the data you can actually access.

this guide follows the extension feature list, README and changelog. the GitHub main manifest was at v0.2.87 when checked on November 19, 2026; store and Android releases can differ, and experimental work in other branches or patches isn't automatically released.

1. installing the version you actually need

  • Chrome, Brave and other Chromium browsers: try the Chrome Web Store listing or the project release instructions.
  • Firefox: use the Firefox listing. the browser-specific package can differ from Chrome.
  • Android: use the separate Android app. it's a native WebView wrapper with shared QoL code, not a desktop extension installed inside Chrome Android.
  • Lite / Custom: check the Lite builder if you only want a selected set of tools. Custom combinations still need testing.
  • Safari / iOS: check the Safari Lite and iOS information pages for the current limits rather than assuming the full desktop build works there.

if you install manually, don't combine old and new extension folders. check the installed version in your browser's extension manager, not just the latest number you saw in a Discord changelog.

2. first setup without turning your browser into a toaster

  1. open SpicyChat and open QoL Settings. the main switch is normally enabled after installation.
  2. start from Minimal, Recommended or Creator, or skip presets entirely and choose features yourself.
  3. open the Features tab to browse the grouped options, and use Find a setting if you know what you want but can't find where it moved.
  4. enable a couple of tools that match what you actually do, then test them on the right SpicyChat page.
  5. before experimenting with imports or automatic changes, make a selective backup under Data & Backup.

most individual features start off. setup presets are convenient, but they can enable several at once. check what the preset selected, especially anything that modifies lists or outgoing messages.

3. finding your way around Settings

the main Settings areas include General, Features, Discovery & Filters, Saved Bots & Lists, Chat List, Chat, Writing & Generation, Personas & Memory, Creator Tools, Appearance & Interface, Browser & Tabs, Data & Backup, Advanced, Changelog and Help. some mobile controls only appear when applicable.

the Command Palette can find actions without opening a dozen panels, and the Control Center brings together data-health checks, backups, useful shortcuts, performance tools and support information. not every setting needs to stay enabled for those screens to open.

if a search result takes you to the wrong panel, note the setting's exact name and the version. feature names can change while the saved setting keys stay the same.

4. browsing bots with filters and presets

bot filters can hide or dim cards using official tags, words, creator details, language guesses, saved state or an exact bot ID. dimming is handy if you want to know something was filtered without losing it completely.

Smart Filter Presets save combinations you use a lot. you can pin favorites and apply them from listing shortcuts. Listing Refill can then request more listing results to fill gaps created by your filters, but it doesn't magically search every bot on the site.

remember that a local QoL block is about QoL presentation. it doesn't automatically change SpicyChat's native recommendation system. language guesses and token estimates can be imperfect, and hidden character fields stay hidden.

the tagging guide explains why a bot's selected tags aren't always the same thing as everything implied by its story.

5. Archive Community Themes and blocking presets

two newer integrations use public Archive data, but they do different things.

Archive Community Themes can warn about suggested themes that a public bot doesn't necessarily have as an official SpicyChat tag. there's a distinction between reviewed evidence and less-certain candidates. a community label isn't guaranteed to describe every possible RP with that bot.

Archive Blocking Presets let you optionally filter recognized franchises, characters or title patterns with your own exceptions. they're preference filters, not a declaration that a bot is dangerous. the matching is deliberately conservative when a title describes a group, an original character or an unclear identity.

both integrations are optional and separate from SpicyChat's own Block button. Archive data being unknown means unknown, not that the bot is confirmed safe or confirmed to match. for what those records mean, see the SpicyChat Archive guide.

6. Favorites, Later, folders and saved bots

the Saved Bots Hub brings together what QoL remembers from Favorites, Later, opened history and other local lists. the Bot Organizer adds your own folders, notes and private tags, without editing anyone's public character.

Favorite history can remember bots you've removed from Favorites, and Recently Seen can help when you forgot which bot you opened earlier. Follow Creators is its own QoL list, not a replacement for any native SpicyChat following feature.

the Bot Status Center helps distinguish accessible, private/unknown and confirmed unavailable bots. missing from search is not the same as deleted. don't purge your local records just because one network request failed.

7. organizing conversations

QoL can add chat-list search, filtering, folders, sorting and some bulk actions. you can separate long-running stories from chats you're just testing, or bookmark a conversation you keep returning to.

Chat Nudges are optional reminders for inactive chats; they don't secretly generate a roleplay reply. saved-chat quick actions can help rename, clone or remove supported chats, so double-check the selected conversation before removing anything.

8. tools inside an actual chat

there are message bookmarks, search inside the current chat, top/bottom navigation, history loading, extra message actions and optional timestamps or generation details. Resend fills the message composer so you can review the text. it isn't supposed to send it immediately or silently overwrite your draft.

some tools add actions around SpicyChat's own buttons. if Edit, Copy or another native action disappears after a website update, test the specific QoL helper with its switch off before assuming the original chat data is damaged.

9. OOC, Reply Instructions and writing shortcuts

OOC presets save instructions you send regularly. Reply Instructions can add global or bot-specific guidance manually, once per session or with each outgoing message. these are visible OOC/chat text, not secret higher-priority system instructions.

the formatting toolbar gives shortcuts for asterisk actions, quotes, bold text, backticks and custom pairs. SpicyChat has native composer formatting too now, so try one set at a time if buttons or auto-closing punctuation seem duplicated.

Helpful style reminder:
{{char}} writes only their own speech and voluntary actions.
{{user}} decides their own dialogue, thoughts and actions.
Keep replies short-to-medium unless the scene needs more detail.

this can help, but no instruction guarantees the bot will never control {{user}}. check the user-control guide if your Greeting or examples teach the wrong pattern.

10. SpicyChat native Memory versus QoL Memory tools

this gets confusing because several things have similar names. native Memory belongs to SpicyChat itself. its newer automatic memory system starts saving after the active chat exceeds context, then roughly every 15 back-and-forths maintains relevant facts.

QoL's native Memory Manager helpers work around the actual SpicyChat controls when available. the experimental Native Memory checks are read-only observations; a successful check isn't proof a new memory was generated, and the feature doesn't rewrite memories by itself.

pinned memory, saved user-added memory and automatic memories don't all work identically. see Memory & Context for the native behavior before enabling another helper to do similar things.

11. Context Keeper — local story facts

Context Keeper is QoL's separate local fact store for each conversation. it can keep notes about lasting events, character changes or agreements, with Strict/Balanced/Broad sensitivity, review tools and recap limits.

saving a fact locally does not automatically send it to the chatbot. you have to insert a recap or enable the optional auto-recall behavior. auto-capture and recall are experimental, and stale facts are supposed to be reviewed instead of silently becoming new canon.

Good continuity fact:
Mira admitted she lost the warehouse key and apologized
to {{user}} during the second night.

Less helpful:
Mira was angry and they talked for a while.

if an event gets retconned, review both your local facts and any native memories. QoL's Context Keeper and SpicyChat's Memory Manager are not the same database.

12. Local Chat Lorebooks and the Private Lorebook Bridge

Local Chat Lorebooks are keyword-based entries tied to a conversation. optional recall can put relevant content into outgoing visible OOC text. that isn't native, invisible Lorebook injection.

Private Lorebook Bridge is more advanced. it can work with private bots and private Lorebooks you own, with ownership checks and reviewed handoff steps. automatic changes or deletions of existing native entries are not something to assume is supported. keep a backup and verify the result on the site.

there's also Global Memory / Baseline Notes for reusable local notes across chats. once again, those reach the model as chat text when inserted, not as hidden platform instructions.

for the basic keyword mechanic, read Lorebooks. for how they differ from Rulebooks and Memories, read the systems guide.

13. Rulebook diagnostics

QoL's optional Rulebook Diagnostics records visible meter changes to help investigate a Rulebook that seems to move at the wrong moment. it's not an editor, doesn't read hidden Rulebook definitions and doesn't guarantee that a complete private trigger history is available.

SpicyChat added Text Meters and hidden individual triggers in November 2026. the official docs have been slower to explain their exact internals, so don't treat a diagnostic log's absence as proof nothing happened. use SpicyChat's own Playtest/trace tools where available.

14. tools for making and editing bots

creator tools include text snippets for {{char}} and {{user}}, Save & Stay, Save & Chat, draft history, backup/history strips, version comparisons, a Creator Workspace and optional creation checks.

Creation Audit flags possible issues, such as missing or short fields, odd tags, large text or Lorebook problems. if QoL couldn't read a field, that's unverified, not proof the field was empty. use the live editor to decide whether a warning is real.

the optional Character Token Optimizer suggests ways to cut repeated wording and shows field estimates. review suggested changes before applying them; shorter doesn't automatically mean better.

Creator Writing Assistant can help with spelling and phrasing. browser AI options depend on browser support; it should not silently rewrite and publish a bot for you.

if you're just getting started, the creation, fields and Greeting guides explain the SpicyChat side of the editor.

15. creator Lorebook tools and importing references

the optional Wiki/Web Lorebook Importer helps turn pasted text or user-chosen pages into draft entries. you'll still want to check keywords, duplicates, and whether the source text is accurate and allowed to be reused.

QoL's native Lorebook backup tools can collect details and entries, including long lists that SpicyChat loads in batches. if an export reports incomplete entries or retries, don't assume it's a complete backup until it's verified.

the native character-card importer, SpicyChat's Lorebook importer, and QoL's own backup restore are different things. using the wrong importer is an easy way to get a confusing error.

16. chat and research exports

the smaller Chat Export tools save selected conversations as TXT, Markdown, HTML or JSON. Bulk Chat & Memory Research Export collects larger sets, can resume through checkpoints, and can include accessible bot metadata, linked Lorebook information and native Memory records where available.

newer versions added a Quick scan, better checkpoints, partial download warnings, and exports that can include Story Moments and Rulebook state. choose the scope you actually need. the resulting ZIPs can be very large and contain private roleplay material.

before sharing a report or export, check what is inside. a normal support report and a full research export have very different privacy implications.

17. local backup, Merge, Replace and recovery

in Settings → Data & Backup, choose the categories you want to export. settings, saved lists, folders, Context Keeper, bookmarks, draft histories and other local datasets can be selected separately. large media and service credentials are handled differently from ordinary portable settings.

when importing, Merge combines supported records while Replace can overwrite the selected local category. i'd always make an export first, especially for folders, blocked lists or story facts you care about.

check the downloaded file exists, isn't empty and contains the categories you intended. don't assume that a success toast automatically proves every record was included.

18. account sync, providers and different devices

QoL Cloud synchronization and downloading a local file aren't the same operation. when syncing, pay attention to device, direction, selected categories and local-versus-cloud counts, especially for Blocked and Later lists.

an experimental GitHub backup provider has also been worked on in the QoL project. its availability depends on the actual build you installed; the v0.2.87 main manifest used for this guide does not by itself prove a universal GitHub provider rollout. if your Settings offers GitHub or Both, follow the on-screen connection and token instructions rather than assuming it is active by default.

the safest sync test is two devices with a small, recognizable list: back up both first, add one test item on one device, sync the intended direction and check that the other device sees exactly that item without removing something else.

19. appearance, accessibility and compatibility

QoL has optional bubble styles, fonts, colors, spacing, chat backgrounds, the Mini Panel, text normalization and interface cleanup. SpicyChat now has its own Chat Appearance with layouts, speaker colors, fonts and composer shortcuts.

if a message suddenly looks wrong, test native appearance, QoL appearance and other browser extensions separately. a missing Send button or duplicated format shortcut is probably a layout/compatibility issue, not a sign your conversation was deleted.

20. performance options and Custom Lite

giant Favorites lists, long conversations and lots of browser tabs can still cause freezes. the newer QoL versions defer more optional modules until they're needed and batch card and message work so disabled features don't keep scanning the page.

Performance modes help reduce some extra work in large chats and inactive tabs. Custom Lite can build a smaller extension with selected features, but not every possible combination has been tested across Chrome, Firefox and Android. keep a known-working build when trying custom packages.

if something gets slower after updating, note which route you're on, how many cards or messages are loaded, and which features you enabled. diagnostics are much more helpful with that context.

21. what's different on Android?

the Android APK has two moving parts: the app's native Flutter/WebView code and the shared QoL web bundle. fixing one doesn't automatically update the other. when reporting a bug, include the APK version and the QoL bundle version.

downloads, file pickers, clipboard, tab switching, keyboard behavior and reload-after-resume issues can come from the native wrapper rather than the browser-extension code. some desktop features also depend on extension APIs that aren't present in the APK.

if you see a 0-byte export, keep the original data, try a small manual export and report the filename and file size. don't erase Settings or app data as your first troubleshooting step.

22. if something breaks

  1. check the installed version and platform. is it Chrome/Brave, Firefox, Custom Lite or the Android APK?
  2. note which page you were using and exactly what you clicked.
  3. turn off the related QoL feature temporarily. test the same action again.
  4. if possible, reproduce it in a spare bot or chat rather than risking your only long-running RP.
  5. use Copy all support info or the diagnostics download. review the file before sending it—don't post tokens, private exports or webhook secrets.
  6. send a clear report through QoL Support or GitHub Issues.

example of a useful report: "Chrome, QoL 0.2.87, on a Lorebook editor with 200 entries. importing JSON shows an error after selecting Merge. here's the exact notice and my redacted support report." that's a lot easier to investigate than "import broken" xD.

23. what i'd actually enable first

  • mostly browsing: bot filters, Recently Seen, Later and maybe one Smart Filter Preset.
  • loads of Favorites: Saved Bots Hub, Bot Organizer and Bot Status Center.
  • long RPs: bookmarks, native Memory tools and carefully tested Context Keeper.
  • creating bots: snippets, draft backups, Creation Audit and the Token Optimizer if you need it.
  • making Lorebooks: entry helpers and backups first, experimental native-writing tools later.
  • keeping data safe: selective local backups before enabling sync or bulk cleanup.

you can always add more later. there's no need to enable 100 settings just because they're there.
