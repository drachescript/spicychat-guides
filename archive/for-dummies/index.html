Archive for Dummies — Find & Rebuild a Missing Bot

a detailed, step-by-step walkthrough for finding a lost bot, checking the evidence, using Recovery Lab and making a new character.

so your favorite bot disappeared. now what?

first, don't delete your old chat or assume everything's gone just because the bot stopped showing up in search. the Archive might still have its public definition, an older version, or at least its name and creator. your own conversation might help fill the gaps too.

this is the beginner walkthrough, based on the Archive's Archive for Dummies page. if you're looking for the other features, stats and integrations, use our full Archive guide.

the important part: what can actually be restored?

the Archive cannot undelete the original bot. it can't restore the original bot ID, connect the old chat to a new bot, retrieve private definitions, contact creators for you or get around platform restrictions. only the creator or SpicyChat can decide whether an original bot can return.

Recovery Lab helps you create a separate new copy using public information that was actually saved, plus evidence you already have permission to use. and a bot that's unavailable might be private, unlisted or temporarily missing rather than permanently deleted.

before you start: keep these things if you have them

you don't need all of these. having even one useful piece of information can make the search easier. but i'd keep the originals rather than rewriting everything from memory.

  • public bot link or UUID: the most reliable way to identify which character you're talking about.
  • character name, full title and creator: especially the creator's @handle if you remember it.
  • screenshots: avatar, title, Greeting and other public fields; screenshots are useful clues but aren't a machine-readable full backup.
  • existing conversation: the old chat, a QoL or S.AI Toolkit export, or a manually copied transcript.
  • older saved cards: if you created the bot, a real JSON/PNG character card or your own Lorebook backup may be better than a reconstruction.
  • dates and version clues: when you used the bot, when it changed, and which version felt familiar.

make a separate folder for the files, preferably on your own device. keep the unedited export in there even if you work on a cleaned copy later. it's much easier to compare evidence when the original files haven't been overwritten.

Example local folder:
Missing-Bot-Recovery/
  bot-link.txt
  screenshot-of-listing.png
  original-chat-export.json
  archive-evidence-notes.txt
  recovery-package.json

These are suggested filenames, not files Recovery Lab creates automatically.

if a file contains private roleplay, treat it like a private conversation, not like something you should upload to a public Discord thread.

1. find the exact bot ID

if you've still got a link, this is the easiest part. the bot ID is a UUID: letters, numbers and dashes. it isn't the character's name or the ID of your individual conversation.

  1. open the character's profile or your existing conversation.
  2. copy the browser URL, or use Share / Copy link if that works.
  3. in a profile URL, find the UUID after /chatbot/. in a chat URL, use the first UUID after /chat/—the next one is the conversation ID.
  4. paste the bot ID or its public profile link into Recovery Lab or the Archive's search pages.
Profile: spicychat.ai/chatbot/11111111-2222-4333-8444-555555555555
Chat:    spicychat.ai/chat/11111111-2222-4333-8444-555555555555/aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee

BOT ID:          11111111-2222-4333-8444-555555555555
CONVERSATION ID: aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee

these are fake IDs for the example. language-prefixed links such as /ru/chatbot/ work similarly. even when a chat header is blank, its URL might still contain the bot ID.

on a phone

try the official app's Share option. if that fails, open SpicyChat in your mobile browser, check your old conversation URL or look through bookmarks and browser history.

when asking someone for help, send the public bot ID or profile URL, not the full private conversation URL. and never share cookies, session tokens or passwords.

what if the link looks weird or doesn't open?

you don't need the page to load successfully to read a UUID from an old URL. the Archive's Recovery Lab looks for a UUID inside the text you paste, so a saved link can still be useful even if the original bot disappeared.

the easiest check is to count the identifiers: a normal bot-profile URL has one bot ID, while a chat URL can have the bot ID followed by a different conversation ID. use the bot one. don't confuse it with a username, a numeric profile ID or a link-shortener address.

if the link comes from a screenshot, don't guess missing UUID characters. try browser history, a bookmark, an old message where you shared the bot, or your existing chat before switching to name-only search.

Recovery Lab needs a valid UUID for direct loading. if you only have a name, start with Archive Search or Public bots and obtain the ID from the matching result first.

2. no ID? search what you still remember

start with the bot's name, title or creator's username. a screenshot with readable text can help, but the Archive doesn't promise reverse-image search.

  1. try Archive Search with the title or a distinctive phrase.
  2. check Deleted bots and Public bots—it might still be available.
  3. search the creator's name and shorter or alternative spellings.
  4. clear any tag filters or locally hidden-bot filters, then compare the result's creator and picture.

the Archive might only have an old search reference, or might never have collected the bot at all. no result doesn't prove the bot never existed.

searching without an ID: a practical order

What you rememberWhere i'd start
exact bot IDRecovery Lab or a direct Archive bot record
character name and titleArchive Search, then compare public and deleted listings
creator's @usernamePublic bots / historical search narrowed by creator
a distinctive line from the GreetingArchive Search for that memorable phrase

no details beyond a vague premisetry related terms, but accept that there may not be enough evidence to identify it safely

make sure you're looking at the correct character before copying anything. common names, reused avatars and similar fan characters can produce false matches.

another common mistake is filtering the search so heavily that a perfectly good result disappears. clear your optional tags, creator or locally hidden-card filters and try again before concluding the Archive missed it.

3. check what the Archive actually saved

open the matching record. compare its name, creator, date and any historical versions before copying text. a newer version might be very different from the character you remember.

Archive resultwhat it means
Saved recordsome real public fields were captured, but it might still be incomplete
Search entry onlythere might be a name or creator without a full character definition
ID onlythe ID was seen but no usable definition might be saved
Deleted / unavailablepublic checks found unavailability; this doesn't restore the original bot
Unknown / inconclusivethere isn't enough reliable evidence for a firm conclusion

if the Personality or Scenario is missing, that doesn't mean the original creator left it empty. it might just never have been collected.

which archived version should you choose?

you might find multiple historical changes for one bot. that doesn't automatically mean every edit was a complete different version, and it doesn't mean all fields were saved equally well.

  1. open the Archive record and compare the saved title, Greeting and other fields with what you remember.
  2. in Recovery Lab, find Base recovery on. choose Latest archived evidence for the most recent saved state, or pick one of the dated older entries.
  3. check the editor and its Archived Original badges after switching. the starting evidence can change with the selected date.
  4. only start adding your own draft text after choosing your base. switching the version resets the editor from the selected archived evidence, so you should export an existing working copy first if you already edited it.

the date selector is built from the Archive's recorded field history. it isn't a time machine that reconstructs an unsaved full snapshot. an old field value is only as trustworthy as the historical evidence that was captured.

understanding the Recovery evidence & readiness panel

after loading the bot, the page shows how many of its eight supported fields have some archived value. this is a presence check, not a score for quality or completeness.

FieldWhat to check
Nameis it the actual character's name or a default title?
Titledoes it describe the original premise, and is it the correct older version?
Greetingis the first playable message complete and in the original writing style?
Personalitywere the defining traits and relationships actually saved?
Scenariois the opening situation present, rather than inferred from a later chat?
Example Dialogueis this real example text or an empty field?
Tagsare they the old recorded tags or tags currently selectable in SpicyChat?
Image URLdoes the link still return a picture and is it the right character?

8 of 8 does not mean 100% authentic or fully complete. some fields might contain short snippets or old values. likewise, 2 of 8 doesn't mean the recovery is useless if those two fields include a long Greeting and Personality.

the panel also gives warnings about missing or weak evidence. use those warnings to decide what needs verification before you start generating guesses.

recovering an archived picture

if a picture is available, the readiness area can show Download archived picture, Use archived picture URL and View image. they're different actions.

  • View image: opens the currently referenced image so you can inspect it.
  • Download archived picture: tries to download the image file to your device.
  • Use archived picture URL: copies or selects the saved image reference for your recovery editor; an old external URL may stop working later.

the saved picture might be a resized version rather than the original upload. if direct downloading fails because the host blocks it, try viewing the image in your browser and using the browser's own save controls where permitted.

if there's no archived picture, don't invent one and label it original. you can pick a replacement you own or have permission to use when you create your new bot.

4. save your old chat while you can

if the old conversation still opens, keep a personal backup before you change or delete anything. that chat may be the best evidence you have for how the character actually spoke.

  1. use an available export tool such as DragonScript QoL (detailed setup below) or S.AI Toolkit, or copy accessible chat text manually.
  2. check that the downloaded file contains real messages; don't trust a filename alone.
  3. keep the original file unchanged. Recovery Lab accepts supported JSON/HTML transcripts, Markdown, plain text, and pasted conversations.
  4. if an export won't load, try a smaller supported transcript or paste some text using the recovery page's text box.

your private chat doesn't need to be publicly uploaded to the Archive. the guide says conversation parsing is handled locally in your browser. optional External AI is different: only use it if you're comfortable sending selected evidence to that provider. nothing can export a chat your account can no longer access.

4a. install DragonScript QoL if you don't already have it

QoL is optional and independent of SpicyChat. You do not need it to search the Archive, and installing it cannot unlock a conversation your account can no longer access.

  1. On a computer, install from the Chrome Web Store (Chrome/Brave/compatible Chromium) or Firefox Add-ons. Confirm installation and permissions.
  2. Open the browser Extensions menu, find SpicyChat QoL, reload SpicyChat, open QoL Settings from the extension popup and check the main switch.
  3. On Android use the separate QoL Android app and its QoL Settings. Desktop is easier for large ZIPs and downloads.
  4. For manual or Lite installation, verify Chat Export is included. See the full installation and update guide for loading packages and checking versions.

4c. export the actual conversation with QoL

  1. Open the old chat itself, not the public profile. Confirm the correct account and conversation. Click the QoL Export control.
  2. Wait for accessible history to be fetched. In v0.3 supported builds save capture checkpoints. If paused or interrupted, reopen Export and resume. Check completeness, not just the native count: deleted, replaced and filtered rows can affect reported counts.
  3. In the normal Chat export dialog click Archive / Recovery Lab. This selects JSON backup and adds bot info, visible Rulebook snapshot/state, available generation details, numbered messages and OOC/directives. It preserves your avatar, image and censor choices. It changes only this export, does not upload anything, and does not expose hidden fields.
  4. If the button isn't present (older builds or the separate large saved-capture dialog), manually select JSON backup and those same evidence options. For a private original leave Export censored copy off. Review if any directive fetch or history fetch is incomplete.
  5. Click Download JSON, or Download saved capture / Save directly to file… in the large-capture dialog. Optionally save HTML archive → Clean transcript for reading. Confirm that the file contains the right speakers and earliest/latest expected messages. Keep the original.
  6. Open Recovery Lab, find Add conversation evidence and choose the plain JSON file, then review detected speakers and the preview. The file parser runs locally.

If the API fetch fails, Retry full chat fetch or Resume / reopen saved capture may be offered. Advanced / Compatibility → Load full chat through page is very slow and only a last resort. If the conversation is no longer accessible, use existing authorized evidence rather than trying to bypass access restrictions.

4c-extra. large and compressed exports

v0.3 adds Pause, Save partial export, Resume fetching, downloaded saved captures and Fetch new messages for supported checkpoint captures. Pause instead of starting over. A partial export can preserve useful evidence, but it is incomplete; label it accordingly. Fetch new messages adds newer history when the saved head is found; older edits or regenerated replies are not revalidated. If older correctness matters, retain the earlier download and start a fresh capture or use the appropriate verification workflow. Do not clear saved captures until the actual downloaded backup is safely stored.

Recovery Lab cannot directly read .json.gz. Choose JSON backup for a straightforward import, or decompress a compressed copy locally using an archive utility supporting gzip. The resulting .json file, not the compressed size, must fit the current 20 MB conversation file limit. Do not rename .gz to .json. If the uncompressed file exceeds 20 MB, keep the full original separately and prepare a smaller valid JSON or speaker-labeled transcript, with enough context to reconstruct the relevant character. A ZIP from bulk Research Export also needs extraction first.

See the full large-export instructions for saved-capture controls, audits, formats and checkpoint storage.

4d. back up many bots and native Memories before you lose them

For one missing bot, use the previous method. For your accessible chat library enable Enable bulk research exports, then click Open research export in a separate tab.

  1. Choose Recent bots to export (default 50) or All bots. Each bot can have multiple conversations.
  2. Choose Reuse cached / update stale under Character metadata and click Start / Resume. Keep every downloaded ZIP part.
  3. Full scan discovers all bots/conversations; Verify all checks older saved histories. Start / Resume is incremental, Scan bots discovers changes and Fresh rebuilds the selected archive from scratch. Do not discard earlier ZIPs or clear checkpoints merely to update the backup.
  4. Extract the ZIP. Look under characters/ for the bot and conversations/ for the conversation. Keep conversation.json, every messages-NNNN.json chunk and available memories, story moments, Rulebook state and OOC records. These are evidence, not character cards.
  5. Recovery Lab does not directly accept ZIP. Use single-chat JSON if possible. If you only have split research files, assemble a valid speaker-labeled transcript in order and review what the importer recognizes.

Do not publish a whole private research archive or send it to public support. The conversation file limit is 20 MB; create a smaller valid transcript if necessary. See the complete Research Export instructions for all controls and backup behavior.

4e. check QoL for saved profile evidence

If the old chat is gone, a previously captured QoL profile may still exist. Search Bot Status Center in Settings, then review Saved Bot Copies / Recovery or Deleted / Unavailable Saved Bots by name, creator or ID. Save the available record; do not use Forget or clear storage.

If the profile is still accessible, enable Add Export to bot profile pages, visit it and download a separate public JSON or HTML snapshot. For a bot you own, a real editor backup or native character card may be more useful. Public copies cannot reveal hidden fields. Keep dated versions separate.

which conversation files does Recovery Lab accept?

the current Recovery Lab file picker accepts .json, .html, .htm, .txt and .md. it tries to recognize common QoL exports, S.AI Toolkit exports and other transcripts with actual chat messages.

FormatWhat to expect
JSONbest when the export has recognizable message arrays, roles and speaker information
HTMLworks if the page contains actual recognizable chat messages or embedded message data
TXT / Markdownsimple transcripts can work, especially with speaker names before each message
pasted textuse Use pasted conversation if you don't have a compatible file
ZIPnot a direct import format; extract an appropriate transcript first
JSON.GZ / GZIPdecompress locally into plain JSON before importing; the uncompressed file must fit the 20 MB limit

the current file upload limit is 20 MB per conversation file. if your export is bigger, make a smaller valid transcript before importing. do not just rename a ZIP to .json or split JSON text at a random character, because that usually breaks the structure.

if a saved HTML page only contains menus, navigation or an empty chat container, it might not have exported actual messages. opening the file and checking for real chat text can save you a lot of confusion.

a simple text example that is easy to parse

Mira: I didn't lose the key. I put it somewhere safe.
User: Where?
Mira: That's the part I'm still working out.

Mira: *She checks her coat pocket again.*
User: You're kidding, right?

speaker-prefixed text is a practical fallback, not a guarantee that every possible transcript layout will parse perfectly. check the imported preview afterward.

don't skip the imported-message preview

after a transcript loads, the page summarizes the detected total, character messages, user messages, OOC/system messages and possible regenerations. there is also Review imported messages and identity.

open that preview and check three things: are the speakers assigned correctly, does the character name match the bot you're recovering, and are the messages actually in a sensible order? a different speaker name can trigger a warning, which is worth investigating before using that transcript as evidence.

the three message-selection switches matter too:

  • Use user messages as relationship/context evidence: enabled by default. this helps reconstruct what the character was responding to, but a user's statement isn't always established world canon.
  • Include OOC/system/directive messages: off by default. enable only when those instructions are genuinely relevant to the character you want to reconstruct.
  • Include possible regenerated/swiped replies: off by default. alternative responses may contradict the actual branch you played.

if the speaker labels or story facts look wrong, use Clear conversation and import the correct transcript. changing the inclusion switches also invalidates draft suggestions that were made using the previous selection.

what happens with a very long chat?

being able to import a long conversation isn't the same as every line being sent to an AI. Recovery Lab keeps a message summary, but its reconstruction prompt uses a bounded sample: currently up to about 140 selected messages and 90,000 characters, with the beginning and end represented when there are many more messages.

this matters if one important detail happened halfway through a massive RP. don't assume the AI saw it just because the import counter says thousands of messages. check the prompt preview or include the important evidence in your own reviewed instructions.

i'd rather use a good, representative chat or a few genuinely useful scenes than dump a completely unrelated history into the reconstruction.

5. rebuild the character in Recovery Lab

open Recovery Lab. the controls have actual names, so here's the order i'd use them in:

  1. Choose a bot. paste its bot ID or public profile URL and click Load archive evidence.
  2. Choose the right version. if the Archive saved older versions, use Base recovery on to choose the one you want.
  3. Check readiness. the panel shows which of the eight supported character fields have data. a present field isn't always complete.
  4. Add conversation evidence. drop a supported export into the page or paste text and select Use pasted conversation.
  5. Review message selection. choose whether user messages, OOC messages or regenerated messages should contribute. they aren't all equally reliable evidence of the character's original definition.
  6. Fill gaps. write missing fields yourself, try Quick Draft (offline), or review optional Browser AI / External AI suggestions. Expand proposes additions to existing fields.

AI suggestions are suggestions, not recovered original text. if the Archive never saved a field, don't label a newly written version as the creator's exact original.

all the ways to fill missing fields

Recovery Lab gives you several options, and they don't all send your data to the same place.

OptionWhat it does
Write it yourselfedit the recovered fields manually, using what you know
Quick Draft (offline)makes an evidence-guided local draft without an AI model
Quick Expand (offline)suggests extra text for an existing field, rather than replacing the archived text
Browser AIuses an optional on-device browser model if your browser supports it
External AIrequires choosing an external endpoint and consenting to send selected evidence
Copy prompt / Download promptlets you use the prepared instructions in a separate tool of your choice

the missing-field suggestion buttons mainly target Personality, Scenario and Example Dialogue. Expand is available for existing narrative fields, including Greeting. the Archived Original is still the reference; accepting a draft changes your editable working copy, not the Archive record.

Quick Draft versus writing it yourself

Quick Draft tries to assemble a simple scaffold from the saved title, Greeting, traits and selected conversation clues. it's handy for getting started, but it doesn't magically know the creator's lost definition. if there is too little evidence, it may say it can't make a draft.

you can edit the proposal before choosing Use this draft, or discard it. if you edit it, that matters for the field's provenance.

Expand without overwriting the original

for saved text that needs more detail, Expand proposes an addition to the editable field. Append makes a User Modified copy. it doesn't rewrite the original archived evidence.

if you only want the authentic wording, don't use Expand at all. a longer Personality isn't automatically a more faithful Personality.

Browser AI: useful, but not available everywhere

Browser AI is an optional on-device model. whether it works depends on the browser, hardware, permissions and feature flags. the page checks whether it seems to be available, and some browsers may need to download a model first.

if it says unavailable or blocked, the Archive cannot force the browser to support it. use Quick Draft / Quick Expand or manually write the missing field instead.

even when Browser AI works, review the suggestion for invented relationships, facts, personality traits or ages. the browser model is helping write a new draft, not fetching lost private text.

External AI: know what you're sending

the optional Direct AI reconstruction panel accepts a chat-completions-compatible endpoint and model, plus a key when needed. using it is a separate choice from importing your chat locally.

  1. open Direct AI reconstruction (optional).
  2. enter the endpoint and model, and an API key only if the provider requires one.
  3. check the destination and evidence preview shown by the page.
  4. read the consent checkbox: I understand selected evidence will be sent to this endpoint.
  5. only then choose Reconstruct with AI, if you're comfortable with that provider.
  6. review the result before applying any proposed text.

the current implementation requires HTTPS for remote endpoints (HTTP is allowed only for localhost). endpoint and model may be remembered in your browser; the API key is kept only in the current page session, not as a saved Archive account credential.

the selected archived fields, instructions and sampled chat evidence can leave your browser when you use an external endpoint. don't paste a random URL from someone else's tutorial and assume it's private. never put an API key in the endpoint URL itself.

if the Archive identifies sensitive or ambiguous source material, some automated suggestions are restricted to safer non-explicit character details. that is not a promise that all historical content or any output is appropriate to republish.

build a reconstruction prompt yourself

you don't have to connect an AI provider to use the prompt builder. after choosing Reconstruct Original or Make It Mine, you can add optional instructions and select Build reconstruction prompt.

then use Copy prompt or Download prompt. the prompt labels archived fields, missing fields, the selected historical version and the conversation evidence. it asks the model to keep those distinctions in the output.

Example optional instructions (written by you):
Keep the archived Greeting and Personality unchanged.
For the missing Scenario, use only facts established
in the recovered conversation. Don't invent a new
relationship, history or setting.

that's an example of something you could enter, not a claim that an AI will obey it perfectly. if you put private conversation evidence into an external service manually, the same privacy caveats apply.

6. reconstruct the original or make your own version?

Recovery Lab gives you two approaches. Reconstruct Original sticks close to available archived evidence; Make It Mine is for an intentionally adapted copy. neither can restore hidden content.

pay attention to the evidence labels:

Labelmeaning
Archived Originaltext actually captured by the Archive
Reconstructednew or inferred text, not proven original
User Modifiedsomething you deliberately changed
Missingnothing was captured for that field

say the chat shows that a character is sarcastic. that's good evidence for writing a sarcastic Personality in your reconstruction. it doesn't prove the original creator used the exact sentence you just wrote.

what do the evidence labels actually mean?

you'll see badges beside the editable fields. they're there for a reason: Archived Original is not the same as Reconstructed, and neither should silently turn into a supposed original creator quote.

BadgeHow i'd treat it
Archived Originalpublic text actually captured by Archive; keep it unchanged if fidelity is your goal
Reconstructeda suggestion based on evidence, not verified original wording
User Modifiedyou edited or appended something to your working copy
Missingno archived value is present for that field

the editor includes Restore archived for fields with saved evidence, Restore reconstruction when an applicable draft exists, and Clear. those can help undo edits, but don't rely on the browser tab as your only backup—export your working copy before making big changes.

an AI may give a low/medium/high confidence estimate for a reconstructed field. that's a description of the evidence support, not proof that the original creator wrote those words.

a full example: rebuilding Mira the warehouse guard

here's a completely fictional example to show the difference between saved evidence and a new reconstruction:

What Archive saved:
Name: Mira Vale
Title: The Guard Who Lost the Key
Greeting: *Mira shuts the gate.* "You're out late."
Personality: [NOT ARCHIVED]
Scenario: [NOT ARCHIVED]

What the old conversation shows:
Mira is suspicious at first.
Later she admits losing a warehouse key.
She eventually apologizes to the user.

What you can honestly reconstruct:
Personality: Mira is initially cautious and proud.
She finds it difficult to admit mistakes, but may
apologize after she trusts someone.

Scenario: A guard at a locked warehouse meets
{{user}} at night.

These are INFERRED DRAFTS, not the creator's text.

now compare that to something like “Mira has always secretly been a royal assassin”. if your Archive record and conversation never supported it, that's a new creative choice. use Make It Mine if you want it, but don't call it recovered lore.

this is also why i'm careful with first encounters and relationship status. something that happened 300 chat messages later isn't necessarily how the bot was configured to behave in its opening Scenario.

7. export the draft and make a new bot

  1. review the eight fields: name, title, Greeting, Personality, Scenario, Example Dialogue, tags and picture.
  2. download a recovery package so you have a local backup. use Copy fields for manual creation.
  3. open SpicyChat's Create → Chatbot editor and place the reviewed information into its matching fields.
  4. if you use a JSON or PNG import, check that it is a supported native character-card format. Archive recovery packages aren't automatically native SpicyChat imports. our import guide covers that difference.
  5. only use images and content you have permission to reuse; keep private recreations private when appropriate. don't use recovery to evade moderation.
  6. save the new character and test it in a new chat.
it will be a new bot. it gets a new ID. your original conversation history, ratings, native memories and private Rulebook values aren't automatically moved over.

and check the download before sharing it. recovery packages exclude raw chat-message text, but the reconstructed fields may include private things taken from your conversation.

which export button should you use?

the current Edit & export area has several options. they have different jobs, so please don't assume every download is a native SpicyChat character import.

the recovery package contains a conversation summary, not the raw conversation messages. the fields themselves can still reveal private details that were inferred from your chat, so open the downloaded file before sharing it.

the Character Card V2 export may include legacy description information in an extension, and its standard Description field may be empty if the original data didn't contain one. that's not the same as missing the SpicyChat Personality field.

why did the character-card PNG fail?

PNG export has to fetch the picture and sometimes convert it in the browser. it can fail even if the character text is perfectly fine.

  • No image URL: choose a picture first or use character-card JSON without an embedded image.
  • Expired or unavailable picture: the old host may no longer return the file.
  • Cross-origin restrictions (CORS): the browser may refuse to let the Archive read and package an external image.
  • Large or unsupported conversion: the current browser image-fetch code rejects pictures over 25 MB and limits very large PNG conversions.

if that happens, download character-card JSON and save the image separately if you can. using an image URL in JSON is not the same as embedding the picture in a PNG.

before you publish the replacement

use the live SpicyChat editor as the final check. a historically saved tag might no longer be selectable, and old fields don't always map one-to-one onto the current creator.

  1. compare the imported or copied text with the archived evidence one final time.
  2. review the title and Greeting to make sure they don't force the new player to act or feel something.
  3. verify the current Persona/POV assumptions and relationship setup.
  4. check the image's permission and whether it still loads.
  5. choose appropriate privacy/visibility settings and valid current tags.
  6. save a separate copy, start a new chat and test a few different replies.

the reconstructed bot does not inherit old chat messages, ratings, saves, links, native memories, or private Rulebook state. a new ID is expected, not a sign that Recovery Lab failed.

if you only want a personal recreation, keeping it Private may be the least confusing option. do not republish other people's hidden definitions or content to bypass platform moderation.

8. what about missing Lorebooks and Rulebooks?

try Deleted Lorebooks or Deleted Rulebooks, along with the public Lorebook/Rulebook directories. old listings, covers and attachment links can exist without a full saved book.

the Archive can't recover a private entry or hidden Rulebook definition just because a public bot referred to it. for building your own new content, use the Lorebook or Rulebook guides.

Lorebooks, Rulebooks and attached-bot relationships

a bot might have had a Lorebook, a Rulebook, or both. if those were public and the Archive recorded them, their titles, links, saved public details and history may help you recreate a broader world.

but a public listing or attachment link is not the full book. a Lorebook cover doesn't prove the entry text was saved, and a Rulebook listing doesn't mean every hidden trigger or private meter configuration can be reconstructed.

the Archive's Public Lorebooks, Public Rulebooks, and their deleted-listing pages are useful for looking for related records. if you have a creator-owned file backup, that's generally better evidence than guessing from the bot's chat.

remember to treat the three resources separately: character (Name, Greeting, Personality...), Lorebook (conditional reference facts), and Rulebook (configured state, meters and triggers). recovering one does not automatically recreate the other two.

a quick privacy check before using AI or sharing files

  • is the bot ID public? then sharing the public bot link is usually enough for someone to help find it.
  • does your screenshot show private messages, profile details or tokens? crop or redact those before asking for help.
  • did you upload a transcript into Recovery Lab? the basic parser is local, but using External AI or manually pasting a prompt into another service can send selected content to that service.
  • did the downloaded recovery package contain inferred private facts? check the reconstructed fields, not just whether it contains the raw messages.
  • are you recreating somebody else's bot? respect the creator's rights and current SpicyChat rules; private use is different from publishing somebody else's definition.

you can ask for troubleshooting help without posting a full transcript. a redacted error, bot UUID, file type and a short description often tell people what they need to know.

9. still stuck?

nothing comes up in search

try the exact ID, title variants, creator, Public bots and historical search. remove filters. the Archive may only have a partial record or none at all.

the mobile app won't share the link

try the browser version, old bookmarks or an existing chat URL. send just the public bot ID when asking for help.

the Archive only has a Greeting or picture

that's all that was captured. supplement it with your own conversation or notes and mark new material as reconstructed.

my conversation export doesn't work

open the file and confirm it contains actual messages. try a supported format or paste a small section into Recovery Lab.

will my old bot and chat come back?

not through the Archive. you can make a separate new character, but its ID and conversation are new.

where can i ask for help?

use the QoL Discord or Archive GitHub Issues. include the public bot ID and a short explanation, not credentials or private exports.

more fixes for less obvious problems

Recovery Lab says the UUID is invalid

check that you're pasting an actual 36-character hyphenated UUID, preferably from a public bot link. don't use the chat ID, creator username or an image URL. you can paste the full SpicyChat bot URL if it contains the UUID.

the record loads, but the fields are mostly empty

look for Search entry only or ID only. the Archive may never have saved the full definition. try another recorded date, a creator-owned backup, or your own chat evidence. a missing field is not proof it was blank in SpicyChat.

the site finds an older version, but it isn't the one i remember

try another option under Base recovery on. compare title, Greeting and dates. old versions depend on what was actually captured, and selecting another base refreshes the working fields.

my file is bigger than 20 MB

the current browser file picker limits conversation imports to 20 MB. create a smaller valid transcript, for example by exporting fewer messages or a single conversation, or paste a representative excerpt. don't simply rename a ZIP or cut a JSON file in half.

the exported HTML opens, but Recovery Lab finds no messages

open the file and check whether it really contains chat content. a browser's “Save page” feature might save only the interface. try a tool-generated conversation export or a simple speaker-labeled text transcript.

the wrong character's messages appeared

open Review imported messages and identity and check the speaker labels. if the export is from another bot, use Clear conversation and import the right one before generating drafts.

the AI keeps inventing extra traits

prefer Reconstruct Original, compare against archived fields, and add narrow instructions referencing the exact evidence. use Quick Draft or write missing fields manually. anything unsupported is still invented, however convincing it sounds.

Browser AI is unavailable

that depends on your browser and device. Quick Draft and Quick Expand work without a model. you can also copy the prompt to a tool you choose, taking care with private content.

an external AI endpoint fails

check HTTPS, endpoint compatibility, model name, your provider key and consent checkbox. only use endpoints you trust. the Archive cannot fix a provider's network or billing issue.

the image-download or PNG button fails

try View image. for character cards, use JSON and save the picture separately. the browser may be blocked by CORS, a missing URL or a conversion limit.

the download says it succeeded, but i can't find a file

check your browser's Downloads list and downloads folder, then inspect the file size and open it. browser download permissions, file pickers or blocked downloads can interrupt saves without changing the original archived data.
