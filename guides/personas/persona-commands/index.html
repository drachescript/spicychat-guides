How to get better Roleplays with Persona

Why Persona Commands work

Most people use a Persona like a character sheet: name, gender, appearance, traits and maybe a little backstory. The guide's main point is that the model reads the Persona as part of the roleplay context, so those same Persona tokens can also tell it how to write the RP.

If the Persona says green eyes, the model can reference green eyes. If it says third-person narration, slow pacing and observable information only, those instructions are also sitting in the context where the model can follow them.

Core principle from the thread: focus on how the AI writes, not on scripting exactly what has to happen.

That makes Persona Commands useful for persistent preferences: prose style, POV, pacing, formatting, how much the environment matters, whether the model can act as {{user}}, and similar rules that you want across a whole chat.

Put important commands first

The guide recommends putting the RP instructions at the top of the Persona, before the normal trait list. It also recommends grouping related rules so the block stays readable: style, pacing, rules, then character/persona details.

You do not need a magic syntax. The structure is mainly for clarity and token discipline.

Style & tone commands

The original guide gives a lot of copyable examples. The useful part is to name the behavior you want rather than hoping the model guesses it.

  • Lean prose: Write in a sharp, lean style. Avoid flowery descriptions.
  • More internal character texture: Weave {{char}}'s thoughts and reactions directly into the narration.
  • Horror: ask for a dark, haunting tone.
  • Space opera: ask for awe and wonder.
  • Perspective: explicitly request first-person or third-person narration.
  • Formatting: define how actions, dialogue and thoughts are displayed.
  • Cinematic: ask for scenes to be described visually, like a film.
  • Noir: ask for a cynical, hard-boiled narrative voice.
  • Pulpy adventure: ask for bold, sensational and high-energy language.

The guide is basically encouraging you to write a job description for the narrator rather than a pile of vague adjectives.

Pacing & focus

Pacing is another thing you can make persistent in the Persona. The thread gives separate examples depending on the kind of RP you want:

  • Slow burn: prioritise atmosphere, mood and environment over fast plot escalation.
  • High action: prioritise immediate stakes, motion and a fast pace.
  • Romance: focus on emotional intensity, yearning and romantic tension.
  • World-building: when a new place appears, give it one or two distinctive sensory or cultural details instead of drowning the reply in generic description.
  • Character depth: use dialogue and behavior that imply history, motives and an internal life instead of explaining everything directly.
  • Longer intimate scenes: the guide suggests explicitly slowing progression and asking for more detail per phase if the model tends to rush.

You can also combine broad genres, but the guide warns that broad instructions can become fuzzy. Focus on drama, adventure and romance can work; relationship drama is clearer if you specifically care about that kind of drama.

Rules to keep the RP in line

Keep control of {{user}}

If the bot keeps writing actions or decisions for the user, the guide suggests positive ownership language:

Portray {{char}}'s actions and reactions only.

Describe {{char}}'s perspective and sensory impressions.
{{user}} controls their own persona and choices.

Stop accidental mind-reading

Another recurring problem is a character reacting to internal narration they should not know. The suggested rule is to make the information boundary explicit:

{{char}} reacts only to observable details:
speech, visible actions and audible cues.

The guide also points out that formatting matters. If you put private thoughts into the same prose as visible actions, the model may still treat them as usable context. Keeping actions, dialogue and private thoughts visually distinct gives the instruction a better chance of working.

Positive commands usually beat long negatives

The thread calls this the "pink elephant" problem: if you keep telling the model not to do something, you keep putting that unwanted concept into the context.

Prefer:
Describe observable details.

Instead of:
Don't read minds. Don't react to thoughts. Don't know hidden information...

Positive wording is not magic, but it tends to be cleaner and wastes fewer tokens. The same idea applies to character behavior: describe what the character should do, rather than writing a huge blacklist of behaviors.

Formatting your Persona

Sequential lines, a short paragraph, brackets or a W++-style block can all work. The thread's preference is simply to keep commands grouped and readable.

[STYLE]{cinematic, sharp/lean}
[PACE]{slow burn}
[RULES]{describe observable details only; {{user}} controls their own actions}

Name: ...
Gender: ...
Appearance: ...
Personality: ...

If you already use W++-like fields, put the command block first and the normal Persona fields underneath. The guide also recommends not wasting too much Persona space spelling out details the model can already infer; reserve the limited space for things that actually matter to the RP.

Troubleshooting

Start a fresh chat after major changes

The guide warns that an old chat already contains old patterns. If you completely rewrite your Persona and keep testing in the same long conversation, the previous context can overpower the new instructions.

Model/settings differences matter

The thread notes that different models obey the same rules differently. It also suggests lower temperature for more reliable instruction-following and warns that very high temperature makes behavior less predictable. Treat those exact setting suggestions as guide-era advice rather than a universal rule for every current model.

Use /cmd for temporary fixes

If you only need something for the next few responses — shorter replies, a role reversal, a temporary change of pace — the follow-up discussion recommends using an in-chat command instead of permanently spending Persona tokens on a rule that is irrelevant most of the time.

Do not over-explain secrets

The guide gives the example that writing secretly afraid of dogs can make the model obsess over that secret. Describing the behavior instead — for example, that the character gets nervous around dogs — can let the trait show naturally without constantly foregrounding it.

Testing Persona

The original guide even includes a deliberately out-of-character "testing Persona" whose job is to make the model answer questions about the bot instead of roleplaying. That is useful as a debugging trick, but it is a test tool rather than something you would normally keep on your RP Persona.

Useful follow-up ideas from the thread

The thread continued for months, and a few additions are worth keeping without making people read every reply:

  • Hidden names: one user added a rule that character names stay hidden until they are actually revealed in-story, which helps with Lorebook-loaded NPCs whose names the user should not magically know.
  • One-off scene behavior: if a preference only matters occasionally, use a chat command when the scene reaches that point instead of burning Persona tokens forever.
  • Overriding preset {{user}} information: people experimented with a rules block that explicitly replaces a bot author's assumed user description with the current Persona's traits.
  • Keep it compact: several working examples boil the whole approach down to a short # RULES block followed by # TRAITS.

A practical compact setup

This is not the only correct format; it just combines the main ideas without trying to stuff every command from the thread into one Persona.

# RULES
—Narrate {{char}}'s perspective only; {{user}} controls their own actions
—React only to observable speech/actions
—Write in third person with a sharp, lean style
—Focus on character-driven dialogue and reactions
—Pace: slow burn
—Use the environment and NPCs when they add something to the scene

# FORMAT
—Actions in asterisks
—Dialogue in quotes
—Private thoughts kept distinct from observable actions

# TRAITS
—Name: ...
—Appearance: ...
—Personality: ...
—Other details that actually matter to the RP: ...

The important part is choosing the handful of directives you actually care about. The thread repeatedly comes back to token space: a Persona full of instructions that are rarely relevant leaves less room for the identity you wanted the bot to remember in the first place.
