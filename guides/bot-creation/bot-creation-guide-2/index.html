Put always-needed character behavior on the card

A recurring point in the thread is that the character's core identity should not depend on a Lorebook trigger. Voice, personality, emotional habits, boundaries and anything the bot needs in basically every reply belong in the Personality/character information.

One contributor summarized the practical priority as: Personality first, then the greeting and scenario; use the Lorebook for extra world/reference material rather than the character's basic identity.

Your greeting is already an example

Dialogue examples are useful when you need to demonstrate a specific response format, but the thread points out that they are not mandatory if the greeting already shows the style clearly.

If you do use examples, make them look like the output you actually want:

*{{char}} makes their way back to the house.*

"Hey, my door is locked."

The model gets more from a concrete example than from a vague instruction such as “write better dialogue.”

Use direct, unambiguous wording

Several replies circle around the same issue: the model can drift when instructions are vague, overloaded or written as long negatives. Short, direct traits and behaviors are easier to interpret.

For example, describing the actual trait you want is usually cleaner than building the description around what the character is not. If the character has broken English, a specific speech pattern/example is more useful than hoping the model infers it from one adjective.

Use Lorebooks for conditional/background information

The thread's practical split is:

  • Personality/card: voice, behavior, core identity, relationship habits, important boundaries.
  • Greeting: the starting scene plus a live example of style/format.
  • Scenario: the current setup and roleplay situation.
  • Lorebook: worldbuilding, places, items, background characters, history, powers or other information that only needs to appear when relevant.

For established/fandom characters, one reply also recommends keeping the always-needed canon boundary on the main card rather than trusting it to a conditional Lorebook entry.

Test the actual behavior, not only the card text

  • If the bot keeps dropping a speech habit, make the wording/example more concrete.
  • Try a different model before assuming the card itself is broken; models can interpret the same bot differently.
  • Do not keep adding more text every time something goes wrong. Overloading the card can make it harder to see which instruction is causing the behavior.
  • Move encyclopedia-style world information out of the card if it does not need to be present in every response.
  • When a specific format matters, demonstrate it in the greeting and keep it consistent during testing.
